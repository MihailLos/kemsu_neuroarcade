# Проверка версии 2.4 — 2 ноября 2026

Первоначальная подготовка выполнялась в `codex/prepare-v2.4-development`. Позже изменения были слиты в `main`. По просьбе пользователя оставлена единственная ветка `main`, а рабочая ветка удалена локально и на GitHub. История коммитов сохранена.

## Структура и изменения

Проект состоит из статической страницы (`index.html`, `style.css`, `app.js`), сервера на стандартной библиотеке Python и пар скриптов запуска/загрузки ресурсов для Windows и macOS. Сборщик не нужен. Файлы интерфейса и игровой логики оставлены без изменений.

На момент проверки `assets/` отсутствует. Режим мыши не импортирует MediaPipe; управление камерой требует предварительной загрузки ресурсов скриптом SETUP. В обоих скриптах указана одна версия tasks-vision: 0.10.21 и одна модель Hand Landmarker. Загрузка ресурсов по сети в этой проверке не выполнялась.

Добавлены `.gitignore`, `data/.gitkeep`, `AGENTS.md`, проверки API и план расширения. `data/records.json` исключён из индекса Git, но оставлен на диске с исходным содержимым `{"bestScore": 0}`. Игнорирование ресурсов, рекордов и кэша Python проверено через `git check-ignore`.

Исправлены два ответа API:

- JSON, который не является объектом, получает 400 вместо ошибки 500.
- Ошибка чтения хранилища при POST получает 500 вместо ответа 400 об ошибке запроса. Повреждённый файл не перезаписывается.

README дополнен прямыми командами запуска, командами проверок для обеих ОС, описанием API и восстановлением повреждённого файла. Исправлено описание переноса старого рекорда: код проверяет старое значение при каждой загрузке страницы, а не только один раз. Дублирующий `README_RU.md` заменён ссылками на основную инструкцию.

## Выполненные проверки

Среда: macOS, Python 3.14. Использована только стандартная библиотека.

`python3 -m unittest discover -s tests -v` — **7 тестов пройдены**:

1. Сервер отдаёт HTML, CSS и JavaScript без изменения содержимого, с запретом кэширования.
2. При отсутствии папки данных возвращает нулевой рекорд; первая запись создаёт каталог и JSON без оставшегося временного файла.
3. После записи 650 процесс сервера полностью завершается и запускается заново. GET возвращает 650; запись 10 сохраняет 650; запись 700 обновляет максимум.
4. Некорректные JSON, типы и диапазоны счёта получают 400 и не меняют файл.
5. Посторонний Origin получает 403, неизвестный POST-маршрут — 404; оба локальных Origin разрешены.
6. Шесть одновременных записей сохраняют максимальный результат 700.
7. Повреждённый JSON, отрицательный рекорд, boolean и отсутствие bestScore дают 500 при чтении и записи; исходный файл остаётся целым.

Тесты используют отдельные процессы HTTP-сервера, свободные порты и временные папки рекордов. Пользовательские данные не используются.

`bash -n START_MAC.command SETUP_MAC.command`, `node --check app.js` и `git diff --check` — успешно.

## Что осталось проверить на целевом компьютере

Штатный порт `127.0.0.1:8767` занят ранее запущенным процессом Python (PID 15188 на момент проверки). Попытка запустить второй `server.py` дала `Address already in use`; чтение уже работающего сервера завершилось сбросом соединения. Этот процесс не останавливался. Для штатного запуска нужно остановить прежний сервер в его терминале, затем запустить актуальную версию. Работоспособность текущего обработчика подтверждена тестами на свободных портах.

Windows и PowerShell в среде проверки недоступны. Команды `py -3 server.py`, резервный вариант `python server.py`, пути и скрипты Windows проверены по коду, без исполнения. Скрипты macOS проверены синтаксически; запуск браузера через START и загрузка MediaPipe не выполнялись.

Полный раунд в браузере, камера, FPS, полноэкранный режим и автономная работа с загруженной моделью требуют ручной проверки по списку из README. Результаты API-тестов не заменяют эти проверки. Минимальные характеристики оборудования не заявлены без замеров на ноутбуках мероприятия.

## Исправление после слияния веток

После операций с Git пользовательский `data/records.json` отсутствовал. Он восстановлен со значением `0`, которое было в последней отслеживаемой версии файла. Более высокого значения в проверенной истории Git нет. Сервер теперь создаёт отсутствующий файл при первом чтении рекорда, даже до первого завершённого раунда. Существующий файл при этом не сбрасывается. Рекорды остаются локальными и не входят в коммиты.

Все семь тестов повторно прошли, включая создание JSON при GET, сохранение максимума и перезапуск процесса. Из отслеживания Git также исключены случайно добавленные файлы `__pycache__`. Правила AGENTS.md и README обновлены для работы в одной ветке. Новые исправления пока не закоммичены и не отправлены на GitHub.

## Исправления рекордов после обратной связи

Выявлено: загрузка страницы повторно переносила большее значение из localStorage в файл; ручная правка файла не обновляла интерфейс; экран результата мог показывать значение до подтверждения записи, а его поле рекорда не обновлялось вместе с HUD.

Автоперенос из localStorage удалён. В интерфейсе файл перечитывается каждые две секунды видимой страницы и при возврате во вкладку. GET и POST выполняются последовательно, зависший запрос прерывается через пять секунд. В конце раунда отправляются только очки этого раунда. HUD и экран результата обновляются вместе по ответу сервера; баннер нового рекорда появляется только после успешного сохранения. Пока идёт сохранение, следующий раунд не запускается. При удалении файла не восстанавливается браузерное значение.

Сервер создаёт отсутствующий records.json при запуске, принимает UTF-8 с BOM и проверяет одинаковый диапазон счёта в файле и API. Пользовательский файл не менялся; проверки используют временные каталоги.

Повторная проверка: **10 тестов Python и 8 тестов Node.js прошли**. Покрыты создание файла при старте без папки data, сохранение после перезапуска, ручное снижение 950 → 100 без перезапуска, удаление файла, Windows BOM, обновление обоих полей, ошибочная запись и запоздалый GET. Node.js используется только для проверок разработчика, зависимостей для запуска игры не добавлено.

В настоящем браузере на временном сервере подтверждены автоматическое обновление HUD после правки файла 950 → 100 без перезагрузки и запуск мышью. Сохранение по завершении и обновление экрана результатов проверены автоматическими клиентскими и серверными тестами. Камера и Windows в этом исправлении не проверялись. После обновления нужно перезапустить сервер и закрыть старые вкладки: уже загруженный прежний JavaScript продолжает работать до закрытия/перезагрузки страницы.

## Баланс раундов и блок времени

Вместо независимого случайного выбора каждого типа блоков введены четыре фиксированных набора по 15 секунд. В основной части 56 обычных блоков, 22 красных, 6 золотых, 5 расширений и 4 блока «+5 СЕК». Порядок и горизонтальные позиции меняются. Бонусы распределяются по участкам этапа, красные не идут более двух подряд, включая стыки. Генерация ограничена по числу попыток и имеет запасной порядок с теми же квотами.

Время подлёта нормировано по высоте поля: 3 секунды на первом этапе, примерно 2 на последнем. Основные блоки появляются не позже 56-й секунды, чтобы успеть долететь до 60-й. Каждые заработанные пять дополнительных секунд открывают набор из 4 обычных, 2 красных и 1 золотого блока. В продлении новых блоков времени нет, итоговый предел — 80 секунд.

Появление идёт по расписанию, а не по сбрасываемому кадровому таймеру. Игровое время учитывает реальное прошедшее время, столкновения рассчитываются шагами не более 50 мс. Бонус +20 за пятёрку начисляется независимо от типа пятого полезного блока. Условия добавлены в меню и README. Прежний рекорд не сбрасывался.

Проверки: **17 клиентских тестов и 10 серверных тестов прошли**, JavaScript и git diff проверены. Для 1000 расписаний проверены квоты этапов, распределение бонусов и ограничение красных серий. Дополнительно проверены крайние значения генератора, одинаковое число появлений при 10/20/30/60/120 FPS, длительность 60/65/70/75/80 секунд, отсутствие новых блоков времени после 60 секунд, подбор времени через столкновение, бонус серии для всех полезных типов, повторный запуск и время подлёта при высоте поля 400/600/1200. Стенд рекордов вынесен в общий помощник tests/helpers/game.cjs.

В браузере на macOS проверены обновлённое меню, запуск мышью и работа полного раунда с блоками времени. На первом временном порту POST был отклонён из-за настройки Origin в тестовом запуске; это не относится к штатному порту 8767. Сохранение результата после 80 секунд и повторный старт дополнительно проверены клиентским тестом с настоящими функциями advanceGame/finishGame/startGame. Временные серверы остановлены. Камера и Windows в этой доработке не проверялись.

## Три жизни и защита сердца

Добавлены три сердца в верхней части игрового поля справа от фирменной плашки. После красного блока снимаются 15 очков, серия и одно сердце. В течение двух секунд после потери следующая жизнь защищена: очки и серия при повторном попадании всё равно теряются, счётчик ошибок растёт. Повторные попадания не продлевают защиту. Защищённое сердце пульсирует, потерянное исчезает с анимацией; для prefers-reduced-motion предусмотрено статическое отображение.

При потере последнего сердца вызывается обычное завершение раунда с сохранением итогового счёта после штрафа. Другие блоки того же физического шага не меняют результат. Повторное завершение при одновременном истечении времени исключено. На экране результатов указана причина остановки. Новая игра и возврат в меню сбрасывают состояние сердец и защиты. Существующие рекорды не сбрасывались.

Проверки: **24 клиентских теста и 10 серверных тестов прошли**. Семь новых тестов проверяют начальные жизни, штраф и серию, точную границу двухсекундной защиты, отсутствие её продления, два красных в одном шаге, сохранение нового рекорда после последней жизни, остановку обработки других блоков, однократное завершение на границе таймера и восстановление сердец при сбросе/повторном запуске.

В браузере на macOS визуально проверены сердца справа от плашки, запуск мышью, уменьшение числа жизней во время полного раунда, обновление рекорда, повторный старт и сброс. Для проверки использовался отдельный временный файл рекорда. Тестовая вкладка закрыта, сервер остановлен. Досрочное завершение после третьей потери и рекорд при этом проверены автоматическим тестом. Windows и камера в этой доработке не проверялись.

## Устранение пауз в потоке блоков

Причина: прежнее расписание завершало появление основной части на 56-й секунде, а продление начинало на 60-й. В каждом дополнительном пятисекундном отрезке блоки появлялись только в первые 2,8 секунды. Получались паузы 4 и 2,2 секунды. Дополнительно последний основной этап был сжат: 28 блоков за 11 секунд, тогда как в продлении оставалось 7 за 5 секунд.

Теперь этапы задают расчётное время подхода к платформе, а появление вычисляется вычитанием времени полёта. Внутри продления интервал составляет 5/7 секунды, включая стыки. Блоки продления заранее появляются только при заработанном бонусном времени. Блоки времени распределены так, чтобы быть доступными до появления первого блока продления: поздний бонус не вызывает залп просроченных блоков. Порядок, квоты, жизни, длительность и начисление очков сохранены; теоретический потолок остаётся 1580. Продление всё ещё спокойнее последнего основного этапа по количеству блоков, но многосекундных пауз нет.

Проверки: **26 клиентских тестов прошли**, JavaScript и git diff проверены. Две новые регрессии проверяют интервалы между соседними появлениями (не более 1,1 секунды во всём плане), равномерность продления и позднее получение 0–4 бонусов на 57,5-й секунде без пауз и залпов. Существующие проверки квот, долёта до конца доступного времени, FPS, сердец и рекордов также прошли. Изменения интерфейса и сервера не понадобились.

## Пошаговое обучение

Добавлена галочка в меню (по умолчанию включена), пять секунд управления без блоков, последовательность код → золото → расширение → время → ошибка, подсветка блока/сердец/HUD и карточки с объяснениями. Пропущенный блок повторяется. Информационные шаги завершаются кнопкой «Далее». На любом шаге можно пропустить обучение и перейти к отсчёту 3–2–1. При отключённой галочке игра начинается сразу.

Обучение использует отдельные состояния training/countdown. Учебный таймер не расходуется; эффекты применяются к учебному счёту. Серии не дают бонусных очков. API записи не вызывается до зачётной игры. Перед зачётным раундом сбрасываются очки, жизни, защита, расширение, бонусное время, статистика и расписание. Сброс отменяет все шаги и отсчёт; отложенных таймеров перехода нет. В скрытой вкладке обучение не проходит само. При недоступном рекорде конец отсчёта ждёт восстановления сервера.

Подсказка о рекорде называет его лучшим результатом на компьютере, поскольку ежедневный сброс не реализован. Перенос настройки обучения в хранилище браузера не добавлялся: галочка сохраняет выбор в пределах открытой страницы. Новые зависимости не добавлены. Меню уплотнено для размещения галочки и кнопок на невысоких экранах.

Проверки: **35 клиентских и 10 серверных тестов прошли**. Девять новых тестов покрывают оба способа запуска, отключение обучения, пять секунд движения, порядок и эффекты блоков, повтор пропущенного блока, подсказки и отсчёт, пропуск на каждом шаге, отмену и скрытую вкладку, отсутствие записи/бонуса серии, восстановление сервера перед стартом. Прежние проверки баланса, жизней, рекордов и сервера также прошли. В браузере на macOS проверены включённая галочка, учебный счёт 45 после пяти блоков, выделение сердец, переход в обычную игру и сброс. Выбор обучения при запуске с камерой проверен автоматическим тестом с имитацией её подключения; реальная камера и Windows не проверялись.

Дополнительно в браузере проверены компактное меню без обрезанных кнопок, движущееся выделение красного учебного блока, пропуск обучения и переход в зачёт. Тестовая вкладка закрыта, временный сервер остановлен.
