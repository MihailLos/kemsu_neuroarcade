# Работа над нейроаркадой

## Как вносить изменения

- Работай автономно в рамках задачи: изучи код, внеси небольшие изменения и проверь результат. Уточняй только то, что нельзя определить из проекта и задания.
- По просьбе пользователя работай в единственной ветке `main`. Не создавай дополнительные ветки и не переписывай историю без прямого указания. Отправляй изменения на GitHub только по просьбе пользователя.
- Не переписывай проект с нуля. Согласованный дизайн и механику «Лови код» меняй только по прямому запросу.
- Не добавляй зависимости без необходимости. Сервер использует стандартную библиотеку Python; сборщик и npm для запуска не нужны.
- Пиши простым человеческим языком: короткие предложения, конкретные действия и примеры. Не добавляй выдуманные данные.

## Требования к игре

- Поддерживай Windows 10/11 и macOS. Используй `pathlib`, относительные пути к ресурсам и UTF-8. Сохраняй оба комплекта скриптов установки и запуска.
- Интерфейс, подсказки, ошибки и инструкции для посетителей должны быть на русском языке.
- После первоначальной загрузки MediaPipe игра должна работать без интернета. Не добавляй CDN-запросы во время игры, внешние шрифты, аналитику или обязательные облачные сервисы.
- Сохраняй управление мышью без камеры и файлов MediaPipe.
- Учитывай слабые ноутбуки: одна распознаваемая рука, ограниченная частота распознавания, ограниченное число частиц. Не добавляй тяжёлые эффекты и модели без замеров на целевом оборудовании.
- Останавливай камеру, обработчики и циклы новой мини-игры при выходе из неё. Не запускай несколько распознавателей одновременно.

## Рекорды и проверки

- `data/records.json` — пользовательский файл, не исходный код. Не коммить его и не перезаписывай при проверках. Структуру `data/` сохраняй через `.gitkeep`.
- Рекорд записывает сервер. Сохраняй проверку входных данных, блокировку конкурентных записей и атомарную замену файла. Меньший результат не должен снижать максимум.
- Проверяй API и сохранение после полного перезапуска: `python3 -m unittest discover -s tests -v` (macOS), `py -3 -m unittest discover -s tests -v` (Windows).
- После изменений интерфейса проверь раунд мышью, меню, повторный запуск и сброс; после изменений камеры — также разрешение/отказ доступа и автономный запуск с локальными ресурсами.
- Проверяй инструкции и скрипты обеих ОС. Если Windows или камера недоступны, явно укажи, что проверено по коду, а что запускалось на деле.
- Основная инструкция — `README.md`; `README_RU.md` содержит ссылку на неё. Обновляй документацию, если меняешь команды, API или структуру проекта.
