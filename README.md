# Институт цифры КемГУ — «Лови код» (v2.4)

Локальная интерактивная игра для профориентации школьников. Игрок управляет платформой ладонью перед камерой (MediaPipe Hand Landmarker) или мышью. За 60 секунд нужно собирать полезный код, избегать красных ошибок и получать бонусы. Игра работает на **macOS и Windows**, а после однократной загрузки модели — **без интернета**.

## Что должно быть установлено

- **Python 3.9 или новее** (рекомендуется 3.11–3.13). Проверка: `python3 --version` на macOS; `py -3 --version` или `python --version` на Windows. Скачать: https://www.python.org/downloads/ . На Windows при установке рекомендуется включить **Add Python to PATH**.
- Современный браузер **Google Chrome, Microsoft Edge или Safari** с поддержкой WebAssembly и доступа к камере. Для тестирования на обеих системах рекомендуем Chrome.
- Встроенная или USB-веб-камера для управления рукой. Для игры мышью камера не требуется.
- **Интернет только при первоначальной загрузке MediaPipe** (либо папка `assets`, перенесённая из ранее настроенной версии). Python-пакеты через `pip` ставить не требуется: сервер использует стандартную библиотеку.

## Установка на macOS

1. Распакуйте ZIP в доступную на запись папку, например `~/Documents/NeuroArcade` (не запускайте непосредственно из ZIP).
2. Откройте приложение **Терминал**. Перейдите в папку с файлами игры, например:

   ```bash
   cd ~/Documents/NeuroArcade
   ```

   Если папка расположена иначе, введите `cd ` (с пробелом) и перетащите папку `NeuroArcade` в окно Терминала, затем нажмите Enter.
3. **Один раз, при наличии интернета** (если нет полной папки `assets`) выполните:

   ```bash
   bash SETUP_MAC.command
   ```

4. Запустите локальный сервер:

   ```bash
   bash START_MAC.command
   ```

5. Должен открыться адрес `http://localhost:8767`. Если браузер не открылся сам, перейдите по адресу вручную.
6. Нажмите «Играть с камерой», разрешите браузеру использовать камеру, либо выберите «Играть мышью».
7. Для остановки сервера вернитесь в Терминал и нажмите **Control+C**.

**Если macOS блокирует запуск `.command`:** используйте указанные выше команды `bash ...` в Терминале. Двойной щелчок по файлам необязателен.

## Установка на Windows 10/11

1. Распакуйте ZIP, например в `C:\NeuroArcade`. Проверьте, что в папке находятся `server.py`, `index.html` и скрипты.
2. Запустите **PowerShell** или **Терминал Windows**. Перейдите в папку игры:

   ```powershell
   cd C:\NeuroArcade
   ```

3. **Один раз, с интернетом**, если нет полной папки `assets`, загрузите модель и библиотеки:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\SETUP_ASSETS.ps1
   ```

   Это одноразовый запуск локального скрипта; постоянного изменения политики PowerShell не требуется. Загружайте архив только из доверенного источника.
4. Для запуска игры можно дважды нажать `START.bat`, либо выполнить из PowerShell:

   ```powershell
   .\START.bat
   ```

5. Если окно браузера не появилось, откройте `http://localhost:8767` вручную. Разрешите доступ к камере.
6. Чтобы завершить игру и сервер, нажмите **Ctrl+C** в окне Терминала и подтвердите завершение при необходимости.

Если команда `py -3` не найдена, попробуйте `python --version`; если Python не установлен, установите его и повторите запуск.

## Работа без интернета

При первом подключении к сети скрипт `SETUP_MAC.command` или `SETUP_ASSETS.ps1` загружает библиотеку MediaPipe, WASM-файлы и модель руки в `assets/`. В дальнейшем **не требуется ни интернет, ни GitHub, ни облачный сервер**. Для переноса на другой компьютер можно скопировать всю папку приложения вместе с `assets/`, если она была успешно установлена. Перед выездом отключите Wi-Fi и проверьте запуск с камерой.

## Рекорды — отдельный файл

Лучший результат сохраняется в:

```text
data/records.json
```

Точное имя — `records.json` (с буквой **s**). Файл не входит в репозиторий: это личные результаты конкретного компьютера. При запуске `server.py` отсутствующий файл создаётся автоматически с `{"bestScore": 0}`. Установка MediaPipe на это не влияет.

Пример содержимого: `{"bestScore": 650}`. Файл — единственный источник рекорда. Старые значения из локального хранилища браузера больше не переносятся и не могут восстановить прежние 950 очков. Завершённый раунд отправляет серверу только набранные в нём очки. Сервер сохраняет максимум между файлом и результатом раунда; интерфейс показывает подтверждённое значение. Если запись не удалась, игра сообщает об ошибке и не объявляет несохранённый результат новым рекордом.

Чтобы изменить или сбросить рекорд, сохраните в `data/records.json`, например, `{"bestScore": 0}`. Сервер можно оставить включённым. Открытая страница перечитывает файл каждые две секунды, а также при возврате во вкладку. Обновляются и верхний счётчик, и поле на экране результатов. Для сброса между участниками сначала закончите раунд или нажмите «Сброс»: текущий раунд при завершении может снова повысить рекорд своими очками. Кнопка «Сброс» возвращает игру в меню, но сама файл рекордов не очищает.

**Не удаляйте файл**, если хотите сохранить результат. При удалении следующий запуск сервера или чтение API создаст нулевой рекорд.

Файл хранится рядом с приложением: рекорд переживает закрытие браузера и перезапуск сервера, а также доступен из другого браузера на **этом же компьютере**. Для переноса рекорда на другой ноутбук скопируйте `data/records.json` вместе с проектом. Если используете разные копии игры, у каждой будет собственный рекорд.

Запускать приложение нужно через `START_MAC.command` / `START.bat` (или `python3 server.py` / `py -3 server.py`), **не** двойным щелчком по `index.html`: файловое сохранение работает через локальный сервер.

## Возможные проблемы

- **Адрес не открывается:** убедитесь, что Терминал с сервером остаётся открытым; проверьте наличие Python.
- **Address already in use / порт 8767 занят:** завершите прежний сервер с помощью Ctrl+C; не запускайте одновременно несколько копий игры.
- **Нет доступа к камере:** разрешите его для `localhost` в браузере и в системных настройках macOS/Windows; проверьте, что камеру не заняла другая программа.
- **Не найдена модель:** проверьте, что в папке `assets` есть `vision_bundle.mjs`, `hand_landmarker.task` и папка `wasm`; повторите скрипт установки при наличии интернета.
- **Рекорд не сохраняется:** распакуйте игру в папку с правом записи; не запускайте из ZIP или защищённого системного каталога. Проверьте `data/records.json`.
- **После обновления показывается старая версия:** остановите прежний сервер и заново откройте `http://localhost:8767`.

## Структура

- `index.html`, `style.css`, `app.js` — интерфейс и игровая логика;
- `server.py` — локальный HTTP-сервер с API `/api/record`;
- `data/.gitkeep` — сохраняет папку в Git; `data/records.json` создаётся при запуске сервера и не отслеживается Git;
- `SETUP_MAC.command`, `SETUP_ASSETS.ps1` — однократная установка модели;
- `START_MAC.command`, `START.bat` — запуск;
- `assets/` — локальные файлы MediaPipe (появляются после установки).

Версия 2.4 не меняет дизайн и механику 2.3; добавлены файловый рекорд и эта документация.

## Запуск без вспомогательных скриптов

Из папки проекта на macOS:

```bash
python3 server.py
```

На Windows:

```powershell
py -3 server.py
# Если Python Launcher отсутствует:
python server.py
```

Откройте `http://127.0.0.1:8767` вручную. Сервер слушает только этот компьютер.
`python -m http.server` не подходит: он не поддерживает API рекордов.
Вспомогательные скрипты сами переходят в папку проекта; прямые команды выше
нужно выполнять из неё. При отсутствии `assets/` можно сразу играть мышью.

## Разработка и проверка

Правила работы описаны в [AGENTS.md](AGENTS.md). Работа ведётся в единственной ветке `main`. Новые ветки не нужны. Текущий проект не требует
`pip install`, `npm install` или сборки. В Git не входят загруженные файлы
`assets/`, пользовательские рекорды и временные файлы Python.
После клонирования запустите установку MediaPipe, если нужно управление рукой.

Проверки сервера на macOS:

```bash
python3 -m unittest discover -s tests -v
```

На Windows:

```powershell
py -3 -m unittest discover -s tests -v
# Либо: python -m unittest discover -s tests -v
```

Тесты запускают отдельные процессы сервера на свободных локальных портах и
сохраняют тестовые рекорды во временные папки. Настоящий `data/records.json`
не меняется. Проверяются статические файлы, первый запуск без `data/`,
запись и перезапуск, сохранение максимума, одновременные запросы,
некорректные данные, правка файла без перезапуска, UTF-8 с BOM и повреждённый файл рекорда.

Для разработчиков с уже установленным Node.js есть отдельные проверки клиентской логики:

```bash
node --test tests/test_records.cjs
```

Они проверяют обновление обоих полей, отсутствие переноса старых 950 очков,
порядок запросов и поведение при ошибке записи. Node.js нужен только для этих
проверок; для игры он не требуется.

API: `GET /api/record` возвращает `{"bestScore": 650}`;
`POST /api/record` принимает `{"score": 650}` и возвращает сохранённый максимум.
Допустим целый счёт от 0 до 1 000 000 000. Ошибочный запрос получает HTTP 400,
недопустимый Origin — 403, ошибка хранилища — 500.
Запись использует блокировку потоков и замену файла через `os.replace`.
Не запускайте два процесса сервера для одного файла рекордов.

Если файл повреждён, сервер не сбрасывает его автоматически. Остановите сервер,
сохраните копию файла, затем исправьте JSON: например, `{"bestScore": 650}`.
Если сервер не запустился из-за повреждённого файла, после исправления запустите его снова.
UTF-8 с BOM, который могут добавлять редакторы Windows, поддерживается.
Очищать локальное хранилище браузера для сброса рекорда больше не требуется.

Перед мероприятием проверьте вручную на каждом целевом компьютере:

1. Запуск скриптом и один полный 60-секундный раунд мышью.
2. Повторный раунд, выход в меню, сброс и полноэкранный режим.
3. Разрешение камеры, отказ в доступе и управление ладонью.
4. Сохранение нового рекорда после остановки и повторного запуска сервера.
5. Запуск с камерой при отключённом интернете и заранее скачанных `assets/`.
